# 0001. React + Vite + TypeScript, SPA без своего сервера

Статус: принят

## Контекст

Нужен веб-клиент, который делается параллельно с Flutter-сайтом из `mobile-app` — на случай, если Flutter
для браузера окажется тяжёлым. Требования:

- Тонкий клиент за логином: SEO и серверный рендеринг не нужны.
- Небольшой сервер, на котором уже живут бэкенд, Postgres и Rauthy: лишний постоянный процесс нежелателен.
- Значительную часть кода готовят агенты: важны предсказуемость, распространённость стека и качество кода,
  который агенты для него пишут.
- Нужны готовые компоненты для дерева, списков, drag-and-drop, модальных окон.

## Рассмотренные варианты

### Как рендерить

|        | SPA (статика)                          | Фулстек-фреймворк (Next.js, Nuxt, SvelteKit) |
| ------ | -------------------------------------- | -------------------------------------------- |
| Прод   | Статика за Traefik, без процесса       | Свой Node-сервер (~100+ МБ RAM)              |
| Модель | Весь код выполняется в браузере        | Часть кода на сервере, часть в браузере      |
| Плюс   | Просто, дёшево, одна модель исполнения | Может держать сессию сам, SSR и SEO          |
| Минус  | Сессию держит кто-то другой            | Два рантайма, больше движущихся частей       |

Сессию в httpOnly-cookie берёт на себя бэкенд (ADR 0003), поэтому главное преимущество фулстек-фреймворка
нам не нужно.

### Какой UI-фреймворк

|                        | React                               | Vue                          | Svelte                              | Angular                                  |
| ---------------------- | ----------------------------------- | ---------------------------- | ----------------------------------- | ---------------------------------------- |
| Модель                 | Компоненты-функции, JSX             | Шаблоны + реактивные данные  | Компилятор, минимум шаблонного кода | Компоненты-классы, DI, сигналы           |
| Что в комплекте        | Только UI, остальное — библиотеки   | Роутер и стор от команды Vue | SvelteKit                           | Всё: роутер, формы, HTTP, DI, тесты, CLI |
| Экосистема компонентов | Самая большая                       | Большая                      | Меньше                              | Меньше, чаще корпоративная               |
| Порог входа            | Средний (хуки, правила перерисовки) | Низкий                       | Самый низкий                        | Высокий (DI, декораторы, остатки RxJS)   |
| Код от агентов         | Лучший: больше всего примеров       | Хороший                      | Хороший, но путают Svelte 4 и 5     | Часто устаревший (NgModules, zone.js)    |
| Объём кода             | Средний                             | Средний                      | Малый                               | Большой                                  |

Angular сильнее остальных там, где важна единая структура большой команды: всё в комплекте, архитектура
с сервисами и DI в духе бэкенда, с версии 21 — zoneless и сигналы по умолчанию. Для маленького клиента
и небольшой команды это больше понятий, чем нужно, а меньший выбор готовых компонентов ощутимее.

## Решение

- **React 19, SPA**, сборка **Vite 8**. В проде — статика из `dist/`.
- **TypeScript 6, strict** (+ `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`). TypeScript 7
  (компилятор на Go) пока не поддерживает `typescript-eslint` — переход отдельным
  изменением, когда поддержка появится.
- **pnpm** (версия в `packageManager`), **Node 26 LTS** (`.node-version`).
- **ESLint** (`typescript-eslint` strictTypeChecked, `react-hooks`, `react-refresh`, запреты
  `dangerouslySetInnerHTML` и браузерных хранилищ) + **Prettier**. Biome рассматривался: быстрее и один
  инструмент, но правила хуков React и типизированный линт у ESLint зрелее, и агенты знают его лучше.
- **Vitest** — тот же конфиг и трансформации, что у Vite.
- **Слой данных — TanStack Query**: кэш серверных данных, повторные запросы, инвалидация после изменений.
- **Клиент API — Orval** (`client: react-query`, `httpClient: fetch`). Из `openapi.json` генерируются
  модели, функции и хуки TanStack Query с именами из `operation_id` (`getMe`, `useGetMe`), — как и требует
  контракт API: `operation_id` = имя метода в SDK. Все запросы проходят через свой `fetch`-мутатор
  (`src/api/fetcher.ts`): cookie сессии и ошибки исключением `ApiError`.
  Рассматривались: `openapi-typescript` + `openapi-fetch` (только типы, хуки пришлось бы писать руками
  на каждый эндпоинт) и `@hey-api/openapi-ts` (похожие возможности, меньше распространён). Zod-схемы
  и MSW-моки Orval тоже умеет — включать, когда понадобятся.
- Роутер и UI-кит выбираются в спеке оболочки (`docs/roadmap.md`, 0001).

## Последствия

- Прод — статика: почти ноль RAM, тот же Traefik, что у бэкенда.
- Сайт не индексируется поисковиками и показывает пустую страницу, пока грузится JS. Для приложения за
  логином это приемлемо.
- Роутинг на клиенте: статический сервер должен отдавать `index.html` на любой неизвестный путь
  (настраивается в спеке деплоя).
- Выбор между этим сайтом и Flutter-сайтом — отдельный ADR, когда оба дойдут до дерева задач.
