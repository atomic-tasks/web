# 0006. Токены в два уровня, `light-dark()`, стеклянные панели со сплошным запасным видом

Статус: принят (спека 0004)

## Контекст

ADR 0004 выбрал React Aria Components со своим CSS на токенах. Токенов пока 12, шкал нет, экранов тоже. Дальше первые
настоящие экраны (спека 0005) в стиле современных iOS-приложений: крупные заголовки, группы-карточки, плавающая стеклянная
нижняя панель. Нужны правила, которые не дадут экранам разойтись и сделают доступность свойством системы, а не ручной проверкой.
Ревью спеки (`scratch/egm/`) показало, что три уровня токенов и набор запасных путей избыточны для двух-трёх экранов.

## Рассмотренные варианты

|                  | Токены в CSS-переменных, 2 уровня        | Tailwind 4 + утилиты                     | Токены в JSON (DTCG) + генерация CSS                                       |
| ---------------- | ---------------------------------------- | ---------------------------------------- | -------------------------------------------------------------------------- |
| Зависимости      | Нет                                      | Tailwind, второй язык стилей             | Генератор (Style Dictionary) и шаг сборки                                  |
| Тёмная тема      | `light-dark()` — одна строка на токен    | `dark:` варианты по месту                | Две темы в JSON, генерация                                                 |
| Цена для проекта | Минимальная; всё читается в `tokens.css` | Нарушает правило ADR 0004 «без Tailwind» | Оправдана, когда токены читает вторая платформа (Flutter-клиент отдельный) |

Стекло:

|                          | Только на панелях управления, один сплошной запасной вид | Стекло везде                | Без стекла (сплошные панели) |
| ------------------------ | -------------------------------------------------------- | --------------------------- | ---------------------------- |
| Читаемость               | Фон ≥72% и сплошной запасной вид                         | Хуже на плотном тексте      | Лучшая                       |
| Нагрузка                 | Одна поверхность                                         | Заметна на слабых телефонах | Нет                          |
| Соответствие направлению | Да                                                       | Да, но перебор              | Нет                          |

Индикатор активного пункта: CSS-подсветка `[aria-current]` (выбрано) против анимированной «пилюли» на JS
(`ResizeObserver` и переменные — единственное состояние в JS ради эффекта) и против CSS anchor positioning (не Baseline).

## Решение

- **Токены — CSS-переменные в два уровня** (`src/shared/ui/tokens.css`): значения (шкалы, цвета схем) и семантика
  (`--color-bg`, `--color-text`…). Компонентные токены — только `--glass-*`, когда нельзя выразить семантикой. Токен добавляется
  вместе с первым потребителем. Темы — `color-scheme: light dark` и `light-dark()` (Baseline Widely available). Составные значения
  (тень) собираются из токенов: через `light-dark()` меняются только цвета.
- **Параметр акцента** `--accent-hue` — вход времени выполнения, а не токен. Допустимый диапазон ограничен тем, где контраст и
  гамма sRGB проверены (спека 0004, «Акцент»).
- **Слои каскада** `@layer reset, base, components`; `theme.css` — первый CSS-импорт; `!important` не используем.
- **Стекло — только на нижней панели.** Один сплошной запасной вид включается общим условием: нет `backdrop-filter`,
  `prefers-reduced-transparency`, `prefers-contrast: more`, `forced-colors`. Непрозрачность фона — не ниже 72%.
- **Контраст** — часть спеки: значения и результат расчёта в `plan.md` (единственный источник); автотеста нет, критерий пересмотра
  записан в спеке 0004 («Решено», п. 4).
- **Размеры целей** — `--target-size` (24px, 44px при `any-pointer: coarse`), текст — в `rem`.
- **CSP**: в прод-коде нет записи стилей из JS и атрибутов `style`; правило ESLint запрещает `style` в разметке.
- **Иконки** — собственные inline-SVG компоненты на `currentColor`, без пакета иконок.
- **Политика браузеров**: Baseline Widely available — без запасных путей; Newly available (`backdrop-filter`,
  `prefers-reduced-transparency`, `oklch()`, `color-mix()`) — с корректной деградацией. Записана в `AGENTS.md`.

## Последствия

- Любое изменение токенов или компонентов проверяется на витрине `/design` (dev) в обеих темах и с эмуляцией настроек доступности.
- Новый цвет или размер — сначала токен (и его контраст в `plan.md`), потом компонент.
- Существующие страницы заметно меняются (акцент, радиус, колонка 720px) — осознанно.
- Токены могут разойтись с Flutter-клиентом; если основным станет Flutter, понадобится общий источник (DTCG) и новый ADR.
- Остальные компоненты дизайн-системы (шапка, списки, статусы) делаются в спеке 0005 вместе с экранами.
