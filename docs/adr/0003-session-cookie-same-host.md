# 0003. Вход через бэкенд с httpOnly-cookie, сайт и API на одном хосте

Статус: принят; вход зависит от спеки «browser sessions» в бэкенде (ещё не написана)

## Контекст

Бэкенд принимает в REST только `Authorization: Bearer` — JWT от Rauthy или personal access token.
CORS не настроен, API и Rauthy на разных хостах. Общие гайдлайны требуют хранить токены на клиентах
в защищённом хранилище платформы — для браузера это httpOnly-cookie, а не `localStorage`.

Варианты:

1. **SPA сама проходит вход (OAuth 2.1 + PKCE)** и шлёт Bearer. Токен — в памяти вкладки; после
   перезагрузки нужен тихий повторный вход в Rauthy. Нужен CORS. Токен доступен любому скрипту на странице.
2. **Бэкенд проходит вход сам (BFF) и ставит httpOnly-cookie сессии.** Токены Rauthy в браузер не попадают.
3. **Фулстек-фреймворк с сервером**, который держит сессию. Лишний Node-процесс в проде (ADR 0001).

## Решение

- **Вариант 2.** Бэкенд получает эндпоинты входа, колбэка и выхода, проходит вход в Rauthy
  (authorization code + PKCE, конфиденциальный клиент), хранит сессию у себя и ставит cookie
  `HttpOnly; Secure; SameSite=Lax; Path=/`. REST принимает либо эту cookie, либо Bearer, как сейчас
  (APK, бот, Claude Code не меняются).
- **Сайт и API на одном хосте:** Traefik отдаёт `/api` и `/health` бэкенду, остальное — статике сайта.
  CORS не нужен, cookie — first-party.
- **Защита от CSRF** на изменяющих запросах: `SameSite=Lax` + проверка заголовка `Origin` бэкендом.
- **Выход:** бэкенд удаляет сессию и отвечает `Clear-Site-Data: "cookies", "storage"`.
- Сайт узнаёт, вошёл ли пользователь, только через `GET /api/v1/me` (`401` — показать вход).
- **До готовности бэкенда** — разработка с personal access token: `ATOMIC_DEV_TOKEN` в `.env.local`,
  dev-прокси Vite подставляет `Authorization: Bearer`. Только локально, в бандл не попадает.

Детали (хранение сессий, продление через refresh-токен Rauthy, время жизни, эндпоинты) — в спеке бэкенда.

## Последствия

- Браузерный код не видит токенов: XSS не может их украсть (но может делать запросы, пока страница
  открыта, — поэтому запреты сырого HTML в ESLint и CSP остаются обязательными).
- Бэкенд получает сессии и CSRF-проверку — отдельная спека и ответственность.
- Тот же вход через cookie может использовать и Flutter-сайт из `mobile-app` — решение за тем репозиторием.
- Сайт обязан жить на том же хосте, что и API; на другом домене вход не заработает без CORS и смены
  `SameSite`.
