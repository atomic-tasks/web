# 0002. Деплой: образ со статикой, compose за Traefik, релиз и выкатка, заголовки безопасности

Статус: согласована (Goldfish-ревью egm-lite, правки внесены)

Решение о сервере статики — ADR 0005. Подход к выкатке повторяет бэкенд (`../backend`, ADR 0011, спека 0006).
Маршрут `/api/` на хосте сайта даёт спека 0008 бэкенда.

## Зачем

Сайт работает только в `pnpm dev`. Чтобы им пользоваться, он должен жить на `WEB_HOST` за тем же Traefik,
что и бэкенд, и выкатываться так же предсказуемо: по тегу, с подтверждением, с откатом. Вместе с этим
появляется то, чего нет в dev-сервере: раздача `index.html` на любой адрес (ADR 0001), правильный кэш
бандла и заголовки безопасности. CSP по ADR 0003 обязательна: httpOnly-cookie не даёт украсть токен,
но внедрённый скрипт мог бы делать запросы от имени пользователя.

## Сценарии

1. **Релиз.** Автор ставит тег `vX.Y.Z` на коммит из `main` (`../guides/releases.md`). Workflow собирает
   образ `ghcr.io/atomic-tasks/web` с тегами `X.Y.Z`, `X.Y`, `latest` и создаёт GitHub Release с
   `deploy.tar.gz` (конфиг стека этой версии) и release notes.
2. **Выкатка.** После релиза джоба `deploy` ждёт подтверждения в environment `production`, затем по SSH
   запускает на сервере `deploy.sh X.Y.Z`. Скрипт берёт конфиг стека из релиза, тянет образ, перезапускает
   контейнер и ждёт, пока он отдаст новую версию. Джоба проверяет снаружи, через Traefik и HTTPS, что
   `https://WEB_HOST/version.txt` — новая версия и что заголовки на месте.
3. **Откат и повтор.** Ручной запуск workflow с версией выкатывает уже опубликованный релиз.
4. **Открыть сайт.** `https://WEB_HOST/` и любой адрес сайта (`/nope`, будущие `/folders/123`) — открываются
   напрямую и переживают перезагрузку: сервер отдаёт `index.html`, адрес разбирает роутер (спека 0001).
5. **Новый релиз у открытой вкладки.** После выкатки перезагрузка страницы получает новый `index.html`
   и новый бандл; старые файлы бандла из кэша браузера не мешают.
6. **Бэкенд остановлен или ещё не выкачен с маршрутом `/api/`.** Traefik не знает роутера бэкенда, запрос
   `/api/...` дошёл до сервера статики → `503`, сайт показывает «Нет связи с сервером» (спека 0001, сценарий 5), а не
   «Что-то пошло не так» от разбора HTML.
7. **Проверка локально и в CI.** `docker build` и `docker run` дают то же, что в проде (кроме HTTPS):
   CI собирает образ на каждый PR и проверяет fallback, кэш, `503` на `/api/` и заголовки.

## Правила и ограничения

**Образ**

- Сборка внутри Dockerfile (multi-stage): `pnpm install --frozen-lockfile`, `pnpm build`, Node и pnpm тех
  же версий, что `.node-version` и `packageManager`. В итоговом образе — только `dist/` и конфиг сервера.
- Сервер — nginx в варианте без root (`nginxinc/nginx-unprivileged`, alpine), порт `8080` (ADR 0005).
- Версия — build-arg `VERSION` из тега, сервер отдаёт её в `/version.txt`. В `package.json` остаётся `0.0.0`.
- В контекст сборки не попадают `.env*`, `node_modules/`, `dist/`, `scratch/`, `.git/` (`.dockerignore`):
  в `.env.local` лежит личный `ATOMIC_DEV_TOKEN`.

**Ответы сервера**

- `/assets/*` — файлы с хэшем в имени: `Cache-Control: public, max-age=31536000, immutable`. Нет файла —
  `404`, без fallback: иначе старая вкладка получит HTML вместо JS-чанка.
- `/api/` и всё под ним — `503` (сценарий 6). Пути сайта не начинаются с `/api` (спека 0001).
- Остальные пути: файл, если есть (`/version.txt` и т. п.), иначе `index.html` со статусом `200`.
  `index.html` и прочие файлы вне `/assets/` — `Cache-Control: no-cache`.
- Заголовки на каждом ответе, включая `404` и `503`:
  - `Content-Security-Policy: default-src 'none'; script-src 'self'; style-src 'self' <два хэша>; img-src 'self' data:;
font-src 'self'; connect-src 'self'; manifest-src 'self'; base-uri 'none'; form-action 'self';
frame-ancestors 'none'`;
  - `X-Content-Type-Options: nosniff`;
  - `Referrer-Policy: same-origin`;
  - `Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=(), usb=()`;
  - `Cross-Origin-Opener-Policy: same-origin`;
  - `Strict-Transport-Security: max-age=31536000` (без `includeSubDomains`: на домене живут чужие хосты).
- Версия nginx в ответах не показывается (`server_tokens off`).
- React Aria вставляет два `<style>` (`usePress`, `usePreventScroll`): они разрешены в `style-src` по хэшу
  (ADR 0005), тест сверяет хэши с установленным пакетом. Любое другое ослабление CSP — только через ADR.

**Стек на сервере**

- Отдельный compose-проект `atomic-tasks-web` в `/opt/atomic-tasks-web`: сайт выкатывается независимо
  от бэкенда. Один сервис `web`, только во внешней сети Traefik, порты на хост не публикуются.
- Роутер Traefik — `Host(WEB_HOST)`; роутер бэкенда `Host(WEB_HOST) && PathPrefix(/api/)` длиннее
  и выигрывает (спека 0008 бэкенда).
- Контейнер: `read_only`, `tmpfs` для временных файлов nginx, `cap_drop: [ALL]`, `no-new-privileges`,
  лимит памяти. CI и локальная проверка запускают образ с теми же ограничениями: иначе они впервые
  проверятся на проде.
- Всё о конкретном сервере (хост, сеть, entrypoint, certresolver Traefik) — в `.env` на сервере и
  в переменных environment `production` GitHub. В репозитории — только `.env.example`.

**Выкатка**

- Как у бэкенда (ADR 0011): ключ CI ограничен на сервере forced command
  `restrict,command="/opt/atomic-tasks-web/deploy.sh"`, передаётся только версия. Тот же пользователь
  `deploy`, отдельная строка ключа.
- Environment `production` в репозитории веба: подтверждение автора, секреты только для `main` и тегов `v*`.
- `deploy.sh` не заменяет сам себя: новая версия ложится рядом как `deploy.sh.new`.
- Перезапуск контейнера даёт секунду-две `502` от Traefik — приемлемо.

## Вне рамок

- Маршрут `/api/` на `WEB_HOST` и переезд бэкенда на `API_HOST` — спека 0008 бэкенда.
- Вход и выход — спека 0003. CSP уже рассчитана на него: вход — переход по ссылке на `/api/v1/auth/login`,
  редиректы на Rauthy CSP не ограничивает.
- Индикатор бэкенда на `/api/v1/health` — после появления пути в контракте (см. «Открытые вопросы»).
- Старые чанки после выкатки. Сейчас ленивых чанков нет, сценарий 5 выполняется. Когда появятся
  `lazy()`-маршруты, открытая до релиза вкладка получит `404` на удалённый чанк: в новом образе только новые
  файлы. Решать тогда (перезагрузка по ошибке загрузки чанка или хранение прошлых `assets/`).
- `data:` в `font-src`: шрифтов нет. Появятся — ослабление CSP через ADR 0005.
- Сжатие заранее (`.br`/`.gz` при сборке), HTTP-кэш на уровне Traefik, CDN.
- Отчёты о нарушениях CSP (`report-to`) — некуда их слать.
- Мониторинг доступности, алерты, логи доступа за пределами `docker logs`.
- Stage-окружение и превью PR.
- Мультиплатформенный образ: только `linux/amd64`, как у бэкенда.

## Открытые вопросы

- **`/health` на хосте сайта.** Спека 0008 бэкенда отдаёт на `WEB_HOST` только `/api/`, а `HealthStatus`
  ходит в `/health`. Решение: бэкенд добавляет `GET /api/v1/health` (правка в `../backend`), веб переходит
  на него после обновления `openapi/openapi.json`. До тех пор в проде индикатор показывает «недоступен»,
  но по случайной причине: nginx отдаёт на `/health` `index.html` со статусом `200`, у строки нет
  `status === "ok"`. Известное поведение, не баг деплоя.
  Блокирует только задачу перевода индикатора, не деплой.
- **HSTS у Traefik.** Если Traefik уже ставит HSTS всем хостам, заголовок в nginx дублирует его. Проверить
  на сервере при первой выкатке; два одинаковых заголовка безвредны, но лишни.
- Размер образа и память контейнера. Локально: образ ~91 МБ (из них ~0,4 МБ — `dist/`, остальное — nginx на
  alpine), память под `smoke.sh` — ~9 МиБ из 64. На сервере — записать после первой выкатки.
