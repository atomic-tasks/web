# 0001. Оболочка: роутер, UI-кит, обработка ошибок API

Статус: реализована

## Зачем

Сейчас сайт — одна страница с индикатором связи с бэкендом. Следующим спекам (деплой, вход, дерево задач)
нужна общая основа: адреса страниц, каркас экрана, набор базовых компонентов и единое поведение при ошибках
API. Если не сделать это один раз, каждый экран будет решать это по-своему.

## Сценарии

1. **Открыть сайт.** Пользователь открывает `/`. Видит шапку (название, имя пользователя, индикатор
   бэкенда) и главную страницу-заглушку: «Дерево задач появится здесь». Пользователя оболочка берёт
   из `GET /api/v1/me`; пока ответа нет — «Загрузка…» вместо содержимого.
2. **Прямая ссылка и перезагрузка.** Любой адрес сайта открывается напрямую и переживает перезагрузку;
   «Назад»/«Вперёд» браузера работают; переход по ссылке — без перезагрузки страницы.
3. **Неизвестный адрес.** `/nope` → страница «Не найдено» со ссылкой «На главную», шапка на месте.
4. **Не вошёл.** `GET /api/v1/me` → `401`. Вместо содержимого — экран «Вы не вошли». Пока входа нет
   (спека 0003), в режиме разработки подсказка: задать `ATOMIC_DEV_TOKEN` в `.env.local`.
   Кнопку «Войти» добавит спека 0003.
5. **Ошибка запроса.** Запрос упал → вместо данных сообщение по-русски и кнопка «Повторить»:
   - обрыв сети или прокси не достучался до бэкенда (`502/503/504`) — «Нет связи с сервером»;
   - прочие `5xx` — «Что-то пошло не так на сервере»;
   - `401` — «Сессия закончилась» (и оболочка показывает экран из сценария 4);
   - `403` — «Нет доступа»;
   - `404` — «Не найдено»;
   - `400`, `409`, `422` — `detail` из ответа бэкенда, если это непустая строка, иначе «Сервер не принял
     запрос»; прочие `4xx` — «Сервер не принял запрос»;
   - не HTTP-ошибка (битый ответ и т. п.) — «Что-то пошло не так».
6. **`me` упал не с `401`.** Сеть, `5xx`, `403` (аккаунт отключён) → вместо содержимого сообщение
   по правилам сценария 5 и «Повторить», которая перезапрашивает `me`. Если пользователь уже был
   известен, а сбой случился при фоновом обновлении, — оболочка продолжает работать.
7. **Сессия кончилась во время работы.** Любой запрос получил `401` → оболочка перезапрашивает `me`
   и, получив `401`, показывает экран из сценария 4.
8. **Ошибка в коде интерфейса.** Экран упал при отрисовке → вместо него «Что-то сломалось» и кнопка
   «Перезагрузить» (перезагрузка страницы); шапка остаётся.

## Правила и ограничения

- Тексты ошибок — из кода статуса; `detail` бэкенда показываем только для `400`, `409` и `422`: это сообщения
  предметной области на русском (problem details, RFC 9457). Тело ответа целиком не показываем; наш код
  его не логирует.
- Повторы запросов: обрыв сети и `5xx` — до 2 повторов (временный сбой может пройти); `4xx` и прочие
  исключения не повторяем — ответ не изменится, повтор лишь задержит сообщение. Мутации не повторяем.
- Оболочка не дублирует правила бэкенда: не проверяет права, не угадывает статусы.
- Адреса страниц — часть контракта: на них могут вести ссылки извне. Как устроен возврат на адрес после
  входа и какие адреса допустимы — решает спека 0003 (с учётом правила о redirect в `AGENTS.md`).
- В адресе — идентификаторы и значения фильтров из перечислений, без текстов задач и папок.
  Пути сайта не начинаются с `/api` и `/health`: их забирает прокси.
- Ошибки API показываются компонентом `ErrorMessage` на месте данных; `throwOnError` и suspense
  не используем, поэтому `errorComponent` роутера ловит только ошибки кода.
- Новые зависимости — `@tanstack/react-router` 1.170 и `react-aria-components` 1.22 (ADR 0004). Без CDN
  и внешних шрифтов (self-hosted, будущая CSP).
- Тёмная и светлая тема — по настройке системы (`prefers-color-scheme`), без переключателя.

## Вне рамок

- Вход и выход, кнопка «Войти» — спека 0003.
- Экраны дерева и задач, первые мутации — спека 0004. Здесь только заглушка главной.
- Раздача `index.html` на любой путь в проде — спека деплоя 0002.
- Загрузка данных в `loader` маршрутов и передача `queryClient` в контекст роутера — когда появятся
  экраны с данными (0004).
- Переключатель темы, локализация, настройки пользователя.
- Отправка ошибок во внешний сервис (Sentry и т. п.).

## Открытые вопросы

Пожелания бэкенду, не блокеры:

- Описать в OpenAPI ответы `400/401/403/404/409` как problem details (сейчас только `422`). Пока клиент
  разбирает `{ status, detail }` сам, с проверкой формы.
- Если недоступен IdP (Rauthy), отвечать `503`, а не `401`: иначе сайт покажет «Вы не вошли» вместо
  «Нет связи».
