# 0003. Вход через бэкенд, сессия в cookie

Статус: реализована (вход на проде проверяется после выкатки — `tasks.md`)

Решение — ADR 0003. Бэкенд — спека 0008 `atomic-tasks/backend` (выкачена в v0.5.0): `GET /api/v1/auth/login`,
`GET /api/v1/auth/callback`, `POST /api/v1/auth/logout`, httpOnly-cookie `__Host-at_session`.

## Зачем

Сайт выкачен (0002), но войти на нём нельзя: экран «Вы не вошли» без кнопки. Вход — первое, без чего нет
ни одного экрана с данными (0005).

## Сценарии

1. **Не вошёл.** `GET /api/v1/me` → `401` → экран «Вы не вошли» с кнопкой «Войти».
2. **Вход.** «Войти» — обычный переход браузера (не `fetch`) на `/api/v1/auth/login?return_to=<текущий путь>`.
   Дальше всё делает бэкенд: Rauthy, callback, cookie, редирект обратно на `return_to`. Сайт загружается заново
   и видит пользователя по `me`.
3. **Вход не удался.** Бэкенд возвращает на `/?login_error=<код>`. На экране входа — сообщение:
   - `access_denied` — «Этому аккаунту вход закрыт»;
   - `expired` — «Вход занял слишком долго, попробуйте ещё раз»;
   - `failed` и любой другой код — «Не удалось войти».
     `login_error` в `return_to` следующей попытки не попадает.
4. **Выход.** Кнопка «Выйти» в шапке рядом с именем → `POST /api/v1/auth/logout` → полная перезагрузка на `/`:
   из памяти вкладки уходят все данные прошлого пользователя (кэш TanStack Query). Ошибка выхода — текст
   `describeApiError` рядом с кнопкой, пользователь остаётся на странице.
5. **Индикатор бэкенда убран.** По спеке 0008 бэкенда `/health` на хосте сайта нет (он отдаёт `index.html`, и
   индикатор в проде всегда писал «недоступен»). Доступность бэкенда видна по `me`: «Нет связи с сервером»
   с «Повторить» (спека 0001).

## Правила и ограничения

- Код сайта не читает и не пишет cookie, не знает о токенах: только `me`, ссылка на вход и `logout`.
- `return_to` — только путь и query текущей страницы (`pathname + search`), без хоста; бэкенд всё равно
  проверяет его сам.
- Ссылка на вход — обычный `<a href>`: клиентский роутер её не перехватывает.
- CSRF для `logout` — забота бэкенда (`Origin`); браузер ставит `Origin` на same-origin `POST` сам.
- Локально: вход через `pnpm dev` (бэкенд с `WEB__ORIGIN=http://localhost:5173`). `ATOMIC_DEV_TOKEN` остаётся
  для работы без Rauthy; Bearer у бэкенда важнее cookie, поэтому для проверки входа токен надо убрать.

## Вне рамок

- Выход из сессии Rauthy (RP-initiated logout) — нет у бэкенда.
- Список сессий, выход на всех устройствах, управление PAT в интерфейсе.
- Отдельная страница `/login`: экран входа — состояние `SessionGate` на любом адресе.
