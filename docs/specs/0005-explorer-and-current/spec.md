# 0005. Экраны «Текущие» и «Проводник»

Статус: реализована без прогресса папок (сценарий 11 ждёт спеку 0010 бэкенда)

Вид и компоненты — спека 0004 (дизайн-система). Прототип — `scratch/prototypes/d.html`. Раньше в roadmap
эта работа называлась «Дерево папок и задач» под номером 0004.

## Зачем

Главная ценность сайта: увидеть, что делать дальше, и отметить сделанное; пройтись по папкам и задачам.
Декомпозицию делает агент через MCP, сайт — для человека (`docs/intent.md`).

## Сценарии

1. **Нижняя панель.** После входа внизу — две вкладки: «Текущие» и «Проводник» (и кнопка «+», см. вне рамок).
   Открывается «Текущие».
2. **Текущие.** Плоский список открытых задач (`todo`, `in_progress`) по убыванию приоритета, который вернул
   бэкенд. У строки: номер, значок статуса, название, путь до папки («Работа › AtomicTasks › Веб-клиент»),
   приоритет. Задачи из неактивных веток (папка на паузе, готова, отменена) не показываются.
3. **Проводник.** Корень — папка «Все задачи» (`/folders/root`). Видно подпапки (приоритет, статус, если не
   активна) и задачи этой папки. Нажатие на папку — переход внутрь; в верхней панели «‹ <родитель>» ведёт
   на уровень выше. Адрес каждой папки свой (`/explorer/<id>`): работают «назад» браузера и жест iOS,
   ссылку можно открыть сразу или отправить себе.
4. **Смена статуса.** Нажатие на значок статуса задачи — переключение «готово ↔ к выполнению», строка
   обновляется сразу (оптимистично), при ошибке возвращается с сообщением. Любой из пяти статусов задачи и
   четыре статуса папки (`active`, `paused`, `done`, `cancelled`) выбираются в окне правки (сценарий 12).
5. **Неактивная ветка.** Внутри папки на паузе/готовой/отменённой весь список приглушён, сверху подпись
   «Ветка неактивна: <статус папки>»; приоритеты показываются, но в «Текущие» эти задачи не попадают.
6. **Пусто.** Нет открытых задач — «Всё сделано» (вкладка «Текущие»); пустая папка — «Папка пуста».
7. **Загрузка и ошибки.** Скелетон списка; ошибка — `ErrorMessage` с «Повторить» (спека 0001); `401` — «Вы не
   вошли» (0003).
8. **Выход.** В верхней панели «Проводника» и «Текущих» — кнопка с именем пользователя (длинное имя
   обрезается многоточием); по нажатию — окно с «Выйти».
9. **Фильтр.** В «Текущие» — переключатель «В работе / К выполнению / Все открытые»; выбор — в адресе
   (`?status=`), чтобы переживал обновление.

10. **Завершённые.** По умолчанию бэкенд скрывает завершённые (`done`, `cancelled`) папки и задачи; в «Проводнике» —
    переключатель «Показать завершённые» (`?closed=1` → `include_closed=true`).
11. **Описание и правка.** В строке задачи и папки под названием — описание серым цветом, обрезанное до одной
    строки. Нажатие на строку задачи или значок пера у папки (нажатие на саму папку открывает её) открывает окно:
    название, описание, вес (ползунок 0,5–2 с шагом 0,1), статус; приоритет только показывается (его считает
    бэкенд). Сохранение — `PATCH` изменённых полей и, если изменился, отдельный `POST` статуса; при ошибке окно
    остаётся с текстом ошибки.
12. **Прогресс папок** («5 из 12») — после выхода спеки 0010 бэкенда (счётчики в `browse_folder`); до этого в строке папки его нет.

## Правила и ограничения

- Клиент тонкий (`AGENTS.md`): приоритет, «активная ветка» и список задач — от бэкенда
  (`priority`, `active_branch`, `list_nested_tasks`). Сайт ничего не пересчитывает и не фильтрует
  «неактивные ветки» сам — только показывает то, что вернул API.
- Все данные — через сгенерированные хуки Orval. Тексты задач и папок — только как текст.
- Структура списков — React Aria `GridList` (клавиатура, фокус, скринридер), а не `div` с `onClick`.
  Строка-папка — ссылка; строка-задача — элемент с действием «сменить статус».
- Статус меняется мутацией с оптимистичным обновлением и откатом; после успеха инвалидируются «Текущие»
  и список папки (приоритеты у соседей не меняются, но ветка может стать неактивной при смене статуса папки).
- Вид, размеры, контраст, движение — по спеке 0004; новых литералов цвета и размеров нет.
- Анимация перехода внутрь/назад — View Transitions (`direction` по глубине), только при
  `prefers-reduced-motion: no-preference` и поддержке API; иначе — мгновенная смена.
- Состояние (папка, фильтр) — в адресе; в `localStorage` ничего (ESLint запрещает).

## Вне рамок

- Создание, перенос, удаление задач и папок, кнопка «+» (после этой спеки — она неактивна/скрыта).
- Перетаскивание (DnD в React Aria — отдельная спека). Вес меняется только в окне правки.
- Поиск, теги, «Входящие» как отдельный сценарий разбора.
- Прогресс «N из M выполнено» у папок в первой версии: в API нет счётчиков, они в спеке 0010 бэкенда (шаг 11 `tasks.md`).
- Офлайн, push, синхронизация между вкладками (кроме обычной инвалидации Query).
- Боковая панель для десктопа (решается открытым вопросом 1 спеки 0004).

## Решено

1. **Прогресс папок:** без него в первой версии; счётчики — спека `../backend/docs/specs/0010-folder-task-counts/`; после её релиза шаг 11.
2. **Источник «Текущих»:** `list_nested_tasks` принимает массив `status` (по умолчанию `in_progress`, `todo`) — один запрос, без
   склейки на клиенте. Проверено по `openapi.json` и спеке бэкенда 0003.
3. **Неактивные ветки:** бэкенд сам не спускается в неактивные подпапки (спека бэкенда 0003) — клиент их не фильтрует.

## Открытые вопросы

Приняты по рекомендации, возразишь — поправим:

1. **Выбор статуса:** тап по значку — быстрый переключатель «готово ↔ к выполнению», все статусы — в окне правки (меню `⋯` убрано как лишнее: проще открыть окно).
2. **Профиль и выход:** кнопка с именем в верхней панели, третьей вкладки нет.
3. **Правка (решено по ходу работы):** окно правки входит в 0005, а не в отдельную спеку; значки — Lucide, контуры скопированы в `shared/ui/icons/` без зависимости.
